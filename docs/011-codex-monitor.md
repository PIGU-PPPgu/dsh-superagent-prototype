# 011 本机 Codex 对话监控

Superagent 可以在同一台 Mac、同一 OS 用户下自动观察 Codex 已持久化的对话，并在面板集中显示需要人工处理的变化。它不向 Codex 线程发消息，不恢复或中断线程，也不修改 Codex 的审批设置。

## 启用

按 [部署说明](006-deployment.md)运行 DSH Superagent 后，在面板的 **Codex 观察** 中点 **开始监控**。监控开关保存在 Superagent 的本机数据库中，服务重启后继续生效。**暂停监控** 停止后续扫描，保留已记录的观察和提醒。无需保持 [本机手动试验](009-codex-read-only.md) 的 GUI 开着。

首次扫描建立游标，并为最近七天有活动的主会话生成简短进展摘要；旧消息不会被当作新的待办。之后约每 30 秒扫描一次，主会话有变化时更新摘要、完成报告或需要人工处理的提醒。子智能体线程只汇总数量和最近活动，不单独调用模型或提醒人。面板默认显示最近七天的主会话，**查看全部** 可浏览更早及归档的主会话。需要处理的对话显示在 **概览** 和 **Codex 观察**；侧边栏 Superagent 图标会为未处理提醒显示圆点。**关闭提醒** 只改变 Superagent 面板记录。

子线程没有记录父会话 ID，或其父会话不在本机清单时，面板分别计数。Superagent 不根据时间、标题或正文猜测父子关系。

模型归纳失败时显示异常并在约五分钟后重试；如果主会话先有新活动，则立即重试。依据不在最新助手消息中的提醒不会展示。

## 自动接单

自动接单默认关闭。开启监控后，可在 **Codex 观察** 中点 **开启自动接单**；开关保存在 Superagent 的本机数据库中。开启前已经存在的失败记录只作为历史基线，不会补接。

开启后，只有新近出现、带最新助手消息证据且增量读取完整的“报告失败”主会话才会创建 DSH Ticket。子线程、归档线程、普通提醒、报告受阻和证据不足的记录不会自动接单。同一主会话的同一失败项只处理一次；失败会在面板显示，约五分钟后允许重试。

成功创建的 Ticket 在主会话行显示 **查看工单**。Ticket 的进展和结果只在 Superagent 中展示，不向原 Codex 线程发送消息，也不恢复或中断该线程。关闭自动接单只停止后续创建，不停止已经创建的 Ticket；暂停监控则同时停止扫描和后续接单。

当本机 Codex 索引记录的 GitHub 仓库与已配置的某个绑定一致时，Ticket 使用该绑定的账号，在自己的目录克隆对应仓库。没有仓库信息或仓库未绑定时，Ticket 进入空目录做诊断，不克隆默认仓库；工作环境提供的 `gh` 和 `git` 命令会拒绝使用默认 GitHub 账号。运行中的仓库工单会锁住其绑定的仓库与 CLI 配置，直到工单结束。

发现线程时只读枚举本机 Codex 会话日志文件，并与本机状态数据库的标题、来源和更新时间关联；对索引缺失的文件只检查有界的首条元信息，排除文件名 ID 与真实会话 ID 不符的重复文件，不读取日志对话正文或修复 Codex 的索引。内容读取只调用 Codex CLI 的 thread/turns/list 和 thread/items/list 只读 RPC。文件已失效、来源无法识别的记录会计入覆盖信息，不伪装成已归纳的主会话；不持久化的临时线程无法枚举。若增量窗口超过读取上限或游标丢失，面板显示读取异常，不会悄悄标为“已处理”。

## 状态与数据边界

独立启动的 App Server 读取的是**已存储历史**。面板的“最近进展”“报告完成”“报告受阻”是对可见消息的归纳，不能证明 Codex Desktop 此刻正在运行或等待审批；本功能不提供实时状态。模型分析只接收有界的主会话用户与助手文本，不接收子线程正文、reasoning、命令输出或文件正文。模型可见的提示和回答保存在 Superagent 私有状态数据库中，供核对；面板接口不返回这些正文。

模型结果是提醒建议，可能判断错误。最新主会话结论会更新摘要并撤销不再需要的旧提醒；用户回复也会清除旧的待答提醒。未开启自动接单时，监控不创建 DSH Ticket；开启后也只接符合上述条件的失败记录，不获得控制 Codex 的权限。
