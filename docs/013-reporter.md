# 013 Reporter：飞书里的远程入口

Reporter 是一个独立常驻进程，把 superagent 的状态推进飞书，并接受飞书里的指令。它不改 DSH 主进程，不新增接口：读取走面板同款的 `/orchestrator/api`，操作走面板已有的那些（停止/重试工单、暂停、确认提醒、取消控制意图、开关监控与自动接单）。

## 采集与推送

进程每 45 秒拉一次 `/orchestrator/api/state`、`/overview`、`/codex`，合并成一份快照。快照里值得打扰人的东西只有几类：Codex 里等你决定的会话、技术异常、新的工单结果或结束、以及健康检查出现异常条目。

推送与否由**指纹**决定：指纹只由这些条目的身份（类型、会话 ID、工单 ID）组成，不含摘要措辞，也不受会话排序影响。因此同一件事只推一次，模型改写摘要不会重复打扰，而真正的新结果一定是一次新推送。指纹存在 `~/.dsh/state/superagent-reporter/state.json`。

每日 `dailyAt` 另推一次全局简报。免打扰窗口只压变化推送，不压每日简报，也不压命令回复。

## 命令

查询：`状态`、`简报`、`待办`、`工单`（`待人`/`进行中`/`已结束`）、`会话`、`健康`。

操作：`暂停`、`继续`、`停止 <工单ID>`、`重试 <工单ID>`、`已读 <会话ID>`、`取消 <意图ID>`、`监控 开|关`、`自动接单 开|关`、`会话控制 开|关`。ID 可以只给前几位，但必须唯一。

只有 `operators` 名单里的 open_id 能执行操作，`readers` 只能查询；名单外的人发消息不会得到任何回应。审批仍然在原界面完成，Reporter 不批准任何请求。

## 与 Codex 控制的边界

Reporter 不直接控制 Codex 会话，也不绕过 DSH 主会话的决策：它只能调用面板公开的接口（读状态、确认提醒、取消**尚未领取**的控制意图）。已经领取或已经送达的操作不会被撤回——这一点与 Codex 桥接器的语义一致。

## 飞书接入

命令经 `lark-cli event consume im.message.receive_v1` 进入，消息经 `lark-cli im +messages-send` 发出，都用机器人身份。应用需要 `im:message.p2p_msg:readonly` 权限，并启用 `im.message.receive_v1` 事件（长连接）。`lark-cli` 的事件流以 stdin 关闭为退出信号，Reporter 因此保持 stdin 打开并在流结束时重启它。

推送目标可以是私聊（`feishu.userId`）或群（`feishu.chatId`）。群模式下只接受该群消息，私聊消息一律按发送者名单处理。

## 失败与边界

- orchestrator 不可达时只记日志，不推送、不重试轰炸；下一轮继续。
- 飞书发送失败同样只记日志，指纹不推进，下一轮会再推一次。
- 推送内容只含摘要与短 ID，不含对话正文、命令输出或凭据。
- Reporter 不执行任意 shell 命令，也没有自由文本入口：能做的事就是上面这张命令表。
